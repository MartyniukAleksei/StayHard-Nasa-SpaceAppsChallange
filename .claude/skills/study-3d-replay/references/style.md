# Стиль 3D replay: StayHard + виняток для сцени

Джерело правди — `docs/design/README.md` і `frontend/src/shared/styles/tokens.css`. Тут лише те, що потрібно для 3D, з поясненнями. Якщо цей файл розходиться з `docs/design/README.md`, правий `docs/design/README.md`; онови скіл.

## Два світи в одній рамці

1. **Усередині рамки сцени** (`<figure class="…-stage">`) — реалістичне «вікно в камеру згоряння»: світіння (Bloom), віньєтка, скляна крапля, PBR-метал. ASCII-фактура тут не використовується. Це виняток з DS, ухвалений для FLEX ([ADR 0007](../../../../docs/decisions/0007-3d-replay.md)); для нового дослідження він діє так само, але тільки в межах рамки.
2. **Усе навколо** (кнопки, шкала часу, readout, підписи кадрів, примітка) — суворий StayHard: прямі кути, без тіней і градієнтів, рамки 1 px `var(--line)`, числа моноширинним шрифтом з одиницями.

Причина розділення: сцена має передати фізику (світло, обсяг), а інтерфейс має виглядати частиною сайту. Склянi панелі з blur з прототипу (`prototypes/experiment-3d`) — це старий стиль, не бери їх.

## Токени (з `tokens.css`)

| Токен | Значення | У 3D replay |
|---|---|---|
| `--void` | `#050505` | фон канвасу (`<color attach="background" args={["#050505"]} />`), фон рамки |
| `--deep` | `#0e0e0d` | фон графіка часу |
| `--line` | `#262624` | рамки, поділки |
| `--ash` | `#8d8d88` | підписи, примітка, події на шкалі |
| `--ink` | `#f1f0ea` | текст, курсор часу, слід руху, лінія d² |
| `--flame` | `#4d6bff` | головний «живий» вимір: видима оболонка полум'я, активна швидкість, кінець полум'я на шкалі |
| `--end-ext/com/dis` | `#6fa384` / `#c8735f` / `#c09a52` | лише текст/мітка фіналу, завжди зі значком `● ○ ◇` |

Шрифти: `--mono` (Geist Mono) для чисел і підписів, `--sans` для тексту. Цілі кліку ≥ 44 px (`--hit`) для головних кнопок, ≥ 32 px для перемикачів швидкості.

## Палітра сцени

Тримайся тих самих ролей, що у FLEX, щоб сцени різних досліджень читались однаково:

| Роль | Ядро (core) | Обідок (rim) | Підпис/лінія в UI |
|---|---|---|---|
| Головна оболонка (видиме / гаряче полум'я) | `#2b45e0` | `#7f97ff` | `var(--flame)` |
| Друга оболонка (UV, OH*, холодне полум'я тощо) | `#5b3fd6` | `#c2b3ff` | `#a99bf0` |
| Третій шар, якщо справді потрібен | узгодь з командою і допиши в `docs/design/README.md` | | |
| Крапля / тіло | `meshPhysicalMaterial` `#dcecff`, transmission 0.9, ior палива | | `var(--ink)` |
| Слід руху | `LineBasicMaterial` `#f1f0ea`, opacity 0.5 | | |
| Світло від полум'я | `pointLight` `#9fb0ff`, інтенсивність ∝ присутності шару | | |
| Метал апаратури | `#dfe6f2` metalness 0.85 roughness 0.3 | | |
| Кераміка | `#f1ede4` roughness 0.7 | | |
| Розжарений дріт | emissive `#ff5a14`, лише коли журнал каже, що він увімкнений | | |
| Стінки камери | `#232a3a`, `side: BackSide`, слабкий emissive від полум'я | | |

Полум'я у FLEX синє не тому, що воно таке на фото (гептанове світиться жовтим від сажі), а тому, що синій у DS означає «живий вимір». Тому колір оболонки — «художній» рівень, і це сказано в примітці. Якщо розробник хоче «фотореалістичний» колір, поясни це правило; змінювати його — рішення команди, а не однієї фічі.

Кожен шар має однаковий колір у сцені, на графіку часу і в readout, і завжди підписаний словами («flame, color camera», «flame, UV camera (OH*)»), бо синій і фіолетовий погано розрізняються.

## Освітлення і постобробка (як у FLEX)

```tsx
<ambientLight intensity={0.25} />
<directionalLight position={[40, 60, 30]} intensity={1.4} color="#bcd4ff" />
<directionalLight position={[-50, -20, -40]} intensity={0.5} color="#6a7cff" />
<Environment resolution={128} frames={1}>  {/* процедурне, нічого не завантажує */}
  <Lightformer form="rect" intensity={3} color="#cfe0ff" position={[0, 6, 4]} scale={[8, 3, 1]} />
  <Lightformer form="rect" intensity={1.2} color="#7f9dff" position={[-6, -2, -3]} scale={[4, 6, 1]} />
  <Lightformer form="ring" intensity={2} color="#b9c6ff" position={[5, 0, -4]} scale={3} />
</Environment>
<EffectComposer multisampling={0}>
  <Bloom mipmapBlur intensity={1.15} luminanceThreshold={0.18} luminanceSmoothing={0.35} radius={0.75} />
  <Vignette eskil={false} offset={0.22} darkness={0.85} />
</EffectComposer>
```
Не завантажуй HDRI з мережі: процедурне оточення важить нуль і не ламається без інтернету.

## Компонування навколо сцени

Повтори сітку `experiment-3d.css` (`.x3d`): сцена ліворуч, колонка кадрів 260 px праворуч, під ними шкала часу, readout і примітка; на ширині ≤ 860 px усе в одну колонку, сцена 4:3. Префікс класів — свій для фічі (наприклад `.c3d-` для CFI), щоб стилі не перетиналися.

Обов'язкові елементи:
- **Фаза** внизу рамки (`figcaption`), моноширинний текст: що відбувається зараз за журналом і даними.
- **Лінійка масштабу** «10 mm at the droplet», ширина оновлюється з відстанню камери.
- **Шкала часу** (SVG): головний ряд `--ink`, шари своїми кольорами, нуль — «ignition» (або назва нуля дослідження), події апаратури пунктиром `--ash`, кінець даних полум'я пунктиром `--flame`, курсор `--ink`; клік і перетягування — перемотка; швидкості 0.25× 0.5× 1×.
- **Readout**: час від нуля зі знаком (`+1.23 s`), числа з одиницями, перемикачі шарів.
- **Примітка під сценою** (`.x3d-note`): «3D replay drawn from measured data, not a recording · test #N. From the data: … Estimate: … To scale: … Illustrative: … Drag to rotate, scroll to zoom.» — перелік збігається з паспортом сцени.

## Не робимо

Скляні панелі з blur, заокруглення й тіні в UI навколо сцени · текст поверх найяскравішої частини сцени · синій як фон · кольори фіналів як заливки · HDRI з мережі · сторонні 3D-моделі без ліцензії й джерела розмірів.
