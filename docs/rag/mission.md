# RAG: місія

## Навіщо
Агент Flame in Freefall має відповідати на **будь-які** питання про дослідження й посилатися на джерело кожного твердження (див. [product/mission.md §9](../product/mission.md)). Частина відповідей лежить у таблицях, частина — лише в текстах: коментарях дослідників, інженерних документах, тест-плані, описі дослідження. RAG дає агенту інструмент `search_docs`, який знаходить у цих текстах потрібні шматки разом з готовою цитатою.

## Місце RAG серед інструментів агента
Агент — це LLM з tool calling: модель сама обирає інструмент, бекенд його виконує, модель відповідає лише з результату.

| Тип питання | Інструмент | Механізм |
|---|---|---|
| «Які тести гептану при 0.7 атм?» | `query_tests(study, filters)` | SQL (`studies/<study>`) |
| «Порівняй 12 і 45» | `compare_tests(ids)` | детермінований diff |
| «Покажи d²(t) тесту 2» | `get_timeseries(id, signal)` | SQL |
| «Чому крапля розірвалась?», «Що таке LOI?» | `search_docs(query, study, test_nos)` | **RAG** |
| «Чому гептан при 0.7 атм не гасне?» | `query_tests` → `search_docs(test_nos=…)` | агент комбінує |

Інструменти — Python-функції в бекенді, що викликають ті самі сервіси, що й REST API для фронта. MCP не потрібен (агент живе в бекенді); його можна додати пізніше як обгортку над тими ж сервісами.

## Що RAG НЕ робить
- **Не дає чисел для відповіді.** Тиск, O₂, K, d₀, тип завершення — лише з SQL-інструментів. Числа в чанках (напр. у таблицях тест-плану) — контекст, не джерело.
- **Не фільтрує тести за умовами** — це `query_tests`.
- Не вигадує цитат: кожен результат уже має поле `citation`.

## Правила
- **Кожна відповідь агента має посилання на джерело** — контракт [ADR 0006](../decisions/0006-citation-contract.md). Кожен hit RAG і кожен результат `studies/flex` несе `Source(url, title, text)`; агент передає їх у Claude API як блоки `search_result`, і API сам повертає цитати з нашим `url` і дослівним `cited_text`. URL: тест → `/api/studies/flex/tests/{n}`, файл/PDF-сторінка → `/api/media/flex/files/…#page=N`, опис і публікації → `https://doi.org/…` (FLEX DOI з `data/flex/about.json`).
- Disruption = «самозгасання не спостерігалось», не «горіло б вічно».
- Тести з ниткою (`ts_fiber`) не змішуємо з вільними краплями — префікс TestSheet-чанка містить `fiber yes/no`. У 8 тестах прапорець суперечить коментарю — `fiber_conflict` (див. [data/flex.md](../data/flex.md)).
- Індекс будується офлайн у `build_db`; API лише читає.

## Масштаб
Ціль — ще ~10 досліджень PSI. Тому з першого дня: колонка `study` і фільтр за нею, мітка дослідження в тексті чанка, модуль джерел на дослідження (`rag/sources/<study>.py`), кеш ембеддингів, контрольний набір питань на кожне дослідження.

## Критерій успіху
`recall@5 ≥ 0.8` на контрольному наборі `backend/src/flame/rag/evalsets/<study>.jsonl` і на відкладеному `<study>_holdout.jsonl`, який не використовується для тюнінгу (`uv run python -m flame.rag.eval --set …`). FLEX: 0.93 і 0.90 (див. [plan.md](plan.md)).
