# 0007 — Агент: власний цикл у бекенді, SSE, стисла історія, дії через підтвердження

**Контекст.** Потрібен агент, що відповідає з даних FLEX з посиланнями, працює з сайтом і будує графіки. Дані — read-only DuckDB на Railway; історію чатів не зберігаємо (ADR 0001); сайт публічний, ключ API платний.

**Рішення.**
- **Модель:** Claude Sonnet 5.5 (Anthropic API), адаптивне мислення, `effort=medium`, server-side fallback.
- **Цикл у бекенді** (`flame/agent`, ручний цикл над `client.beta.messages.stream`): інструменти — виклики наших сервісів in-process, без MCP і без text-to-SQL. Відповідь — Server-Sent Events.
- **Стисла історія на клієнті:** фронт надсилає текст реплік і джерела; сервер без стану. Thinking-блоки між запитами не передаються (повне прибирання дозволене); у межах відповіді — append-only.
- **Цитати** — блоки `search_result` (ADR 0006); твердження з числом без цитати → один перезапит, далі «No source».
- **UI-дії — пропозиції з підтвердженням** користувача; підсвічування — одразу. Графіки — декларативна специфікація, дані рахує бекенд.
- **Ліміти й витрати:** IP-ліміт, кроки, токени, стеля витрат процесу; жорсткий ліміт — в Anthropic Console. Кожне спрацювання пояснюється в UI.

**Наслідки.**
- (+) Повний контроль над інструментами, цитатами й лімітами; ключ лише на сервері; клієнт не може підробити результати інструментів.
- (+) Перевірка якості без мережі (фейковий клієнт) і платний eval за бюджетом.
- (−) Відповідь 10–25 с; кожен крок — окремий виклик моделі. Переранжування RAG на Railway додає ~2–3 с на пошук.
- (−) Між репліками модель не пам'ятає своїх міркувань і результатів інструментів — лише текст відповіді й список джерел.
