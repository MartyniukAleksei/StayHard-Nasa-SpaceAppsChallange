# 0008 — Кілька досліджень в одній БД: схема DuckDB на дослідження, знімки кількома архівами

**Статус:** прийнято, 2026-11-15

## Контекст
До FLEX додались знімки п'яти досліджень PSI: CFI, ACME CFI-G, BASS-II, SAME-R, Saffire-II ([data/psi-studies.md](../data/psi-studies.md)). Кожен знімок має ту саму будову, що `data/flex/`, і свої таблиці `tests`, `test_files`, `ts_*` з різними колонками. Разом це архів 1.6 ГБ (розпаковано 1.98 ГБ), з якого таблиці DuckDB займають лише ≈ 42 МБ, а решта — mp4, pdf і сирі файли. GitHub Release приймає asset до 2 ГіБ. Код API, RAG і агента написаний під FLEX у схемі `main`.

## Рішення
- **Схема на дослідження.** `build_db` копіює таблиці `data/<slug>/<slug>.duckdb` 1:1 у схему `<slug>` тієї ж `flame.duckdb` (`cfi.tests`, `cfig.ts_telemetry`, …). FLEX лишається в `main`, а схема `flex` містить view на його таблиці. Реєстр `main.studies` описує всі дослідження (slug, accession, DOI, ключ тесту, таблиці), а `study_about` отримує `about.json` кожного.
- **Знімок — архів у GitHub Release, БД — похідна.** `psi-studies-v1.zip` публікується релізом `data-psi-studies-v1`, а `flame.duckdb` збирається з нього на Volume. Так само вже працює `data-flex-vN`.
- **Кілька архівів.** `DATA_ARCHIVE_URLS` — це список. `bootstrap` качає кожен архів окремо, замінює лише каталоги, які в ньому є, і пам'ятає URL у `.archives.json`. Архів можна оновити або розбити на кілька частин (наприклад, по одній на дослідження), не чіпаючи інших.

## Розглянуті альтернативи
- Префікс у назві таблиці (`cfi_tests`): ламає відповідність джерелу й незручний для запитів «одне й те саме в кожному дослідженні».
- Одна таблиця `tests` з колонкою `study`: колонки досліджень майже не перетинаються, тож вийшла б широка розріджена таблиця.
- Окремий сервіс БД (Postgres на Railway): суперечить [ADR 0001](0001-duckdb-single-file.md), а дані статичні.
- Окремий файл DuckDB на дослідження з `ATTACH` у рантаймі: більше рухомих частин, а RAG і реєстр усе одно потребують спільного файлу.

## Наслідки
- Існуючий код FLEX не змінюється. Нові модулі запитують `<slug>.<table>`.
- Сирі дані інших досліджень не нормалізуються. Обробка, якщо знадобиться, додається кодом у `build_db` / `psi_studies` (`BUILD_SOURCES`).
- Volume має вмістити FLEX, знімки, БД і тимчасовий zip найбільшого архіву (≈ 4.3 ГБ піку при першому старті з одним архівом 1.6 ГБ).
- RAG, агент і UI для нових досліджень — окремі задачі.
