# 0001 — БД: один read-only файл DuckDB (+ вектори в ньому ж)

**Статус:** прийнято, 2026-11-15

## Контекст
Дані — 274 тести FLEX, ~50 МБ часових рядів, кілька тисяч RAG-чанків (коментарі TestSheet, ~15 МБ PDF, анотації публікацій). Після збору з PSI дані не змінюються. Історію чатів не зберігаємо. Хостинг — Railway.

## Рішення
Один файл `flame.duckdb`, який офлайн збирає `flame.ingest.build_db`: структуровані таблиці, часові ряди і таблиця `chunks` з ембеддингами. Векторний пошук — `array_cosine_similarity` (brute force достатньо для тисяч чанків) або HNSW-індекс розширення `vss`. Бекенд відкриває файл `read_only`.

## Розглянуті альтернативи
- Postgres + pgvector — окремий сервіс (~$5 на місяць), міграції й завантаження даних; переваги (запис, конкурентні транзакції) нам не потрібні.
- DuckDB + LanceDB — другий формат даних без потреби.
- Postgres + Qdrant — надлишково для нашого обсягу.

## Наслідки
- Немає сервісу БД, нульова адміністрація; аналітичні SQL по рядах швидкі.
- Оновлення даних = перезбірка файлу і заміна на Volume.
- Якщо знадобиться запис (історія чатів, акаунти) — переглянути рішення (Postgres).
