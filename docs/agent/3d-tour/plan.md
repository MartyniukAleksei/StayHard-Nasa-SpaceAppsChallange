# 3D-тур агента — план реалізації

Перед стартом прочитати: `mission.md` і `techstack.md` (ця тека), `CLAUDE.md`, `docs/agent/README.md`, `docs/agent/ui-actions.md`, `docs/decisions/0006-citation-contract.md`, `0007-agent-architecture.md`, `0007-3d-replay.md`. Фронтенд робити **лише** за скілом `stayhard-frontend`.

## Погоджені рішення (2026-11-15)

| # | Рішення |
|---|---|
| 1 | Тур запускається **автоматично, без підтвердження**, з будь-якої сторінки. Головне — плавно. Це змінює контракт «агент лише пропонує» (`ui-actions.md`), тож зафіксувати в ADR 0009 і оновити `ui-actions.md`. Решта навігації (`propose_action`) лишається кнопками. |
| 2 | Тур іде сам; є `[Pause]`, `[Next]`, `[Replay]` (і `[Exit tour]`). |
| 3 | Лише фіксований перелік: моменти, ракурси, об'єкти, дії; ≤ 6 кроків, ≤ 2 підписи на крок. |
| 4 | Числа в підписах підставляє бекенд через заповнювачі; модель цифр не пише. |
| 5 | Справжній кадр NASA поруч, виділений на паузі кроку, з тим самим підписом (в межах цього етапу). |
| 6 | Розмітку фото й відео відкладено; робимо лише 3D. |
| 7 | Демо-кейс — холодне полум'я, основний тест #155 (див. `mission.md`); контраст підбирається на кроці 4. |
| 8 | На 375 px: підписи по одному внизу сцени, біля об'єкта — маркер-точка. |
| 9 | Сажову оболонку з атласу не переносимо. |

## Процес

- Кожен крок нижче — окремий PR з feature-гілки в `main` (`feature/agent-tour-backend`, `feature/agent-tour-scene`, `feature/agent-tour-demo`).
- Перед PR — `ruff check`, `ruff format --check`, `pytest` і `npm run build`, `npm test`.
- Мердж — після зеленого CI, перевірки в браузері (десктоп і 375 px) і перевірки проду після автодеплою.
- Не чіпати інфраструктуру Railway, GitHub Releases, `data/flex`, `flame.duckdb`. Не комітити чужі незакомічені файли: `.claude/launch.json`, `AGENTS.md`, `psi-studies-v1.zip`.
- Спільний код (`frontend/src/shared`, `core/config.py`) — окремим маленьким PR, якщо знадобиться.
- Гроші на живі перевірки й eval: облік у `data/agent_spend.json`. Не більше $1 на прогін, загальний ліміт розробки $10: перевірити поточну суму перед стартом. Ключ API — лише в `backend/.env`, ніколи не в коді, логах чи PR.

## Крок 1 — бекенд: `show_in_3d` і подія `tour` (PR 1)

1. **`media/timing.py`:** `apparatus_events(test_no, cir_id) -> {needles_retract, igniter_on, igniter_retracted}` у секундах від запалювання. Мітки й логіка — як у `frontend/src/features/experiment-3d/lib/log.ts`. Тест на реальному фрагменті логу (той самий, що в `log.test.ts`).
2. **`studies/flex/tour.py`** (чисті функції + `cur`):
   - `resolve_moment(test, series, events, moment, t_s) -> float`;
   - `values_at(series, t) -> {d, d2, flame_d, flame_d_uv}` з допуском ±0.25 с;
   - `fill(text, values, prev_values, test_row) -> (text, used_sources, tags)`;
   - `validate(steps)` — перелік, ліміти, заборона цифр поза заповнювачами (дозволено «#155» / «FLEX-155»).
3. **Інструмент `show_in_3d`** у `agent/tools.py`. Вхід:
   ```json
   {"test_no": 155,
    "steps": [
      {"moment": "ignition", "action": "play", "speed": 0.5, "camera": "flame", "focus": ["flame_uv"],
       "labels": [{"at": "flame_uv", "text": "UV flame grows to {flame_d_uv}"}]},
      {"moment": "extinction", "action": "pause", "camera": "droplet", "focus": ["droplet"],
       "labels": [{"at": "droplet", "text": "Flame out at {t}; droplet still {d}"}]},
      {"moment": "t", "t_s": 15, "action": "pause", "camera": "droplet", "focus": ["droplet"], "show_frame": true,
       "labels": [{"at": "droplet", "text": "No visible flame, yet the droplet lost {d_change} in {dt}"}]}
    ]}
   ```
   - `action ∈ play | pause`;
   - `camera ∈ overview | flame | droplet | camera_view`;
   - `focus`/`at ∈ droplet | flame_color | flame_uv | trail | needles | igniters | frame`.

   Вихід: подія `tour {id, test_no, steps:[{t, action, speed, camera, focus, show_frame, labels:[{at, text, tags, source}]}], sources}` і для моделі — `search_result`-джерела з усіма підставленими значеннями (як у `make_chart`). Так текстова відповідь моделі може їх цитувати.
4. **Промпт** (`agent/prompt.py`): коли викликати (питання про перебіг одного тесту, «покажи», «чому згасло»); не більше одного туру на відповідь; холодне полум'я — лише як висновок NASA з цитатою коментаря; без цифр у підписах.
5. **Тести:** `tests/test_tour.py` (моменти, допуск, заповнювачі, валідація, відмова для тесту без рядів чи логу), `tests/test_agent*.py` (фейковий клієнт → подія `tour` у потоці, у `search_result` є підставлені значення).
6. **Документи:**
   - ADR `docs/decisions/0009-agent-3d-tour.md` (автозапуск, режисер, заповнювачі);
   - `docs/agent/ui-actions.md` (подія `tour`, параметр URL `tour=`, подія `window` `agent:tour`, ключ `sessionStorage`);
   - `docs/agent/README.md`.
7. **Eval:** +3 кейси в `agent/evalsets/agent_psi69.jsonl`, прогін `uv run python -m flame.agent.eval --budget 1.0`.

**Готово, коли:** CI зелений; живий запит «What happens in test 155?» локально дає подію `tour` з правильними числами (звірити з `/api/studies/flex/tests/155` і рядами); eval не гірший за поточний (19/22).

## Крок 2 — фронтенд: режисер у 3D-сцені (PR 2)

Скіл `stayhard-frontend`, префікси класів `x3d-`, `ag-`.

1. **`experiment-3d/lib/tour.ts`** + `tour.test.ts`: спец → таймлайн (тривалості з довжини тексту 2.5–6 с, переходи часу як scrub або швидкість, черговість переліт → пауза → підписи).
2. **`lib/playback.ts`:** `scrubTo(t, durationS)` і плавна зміна швидкості. Тести на чисту частину (easing).
3. **`Scene.tsx`:**
   - реєстр якорів (ref на краплю, оболонки полум'я, слід, апаратуру);
   - tween камери з `easeInOutCubic`;
   - вимкнення `autoRotate` під час туру;
   - `Selection` / `Outline`;
   - `Html`-підписи (на ≤ 600 px — маркер-точка).
4. **`TourDirector.tsx`** і смуга керування (`[Pause]`, `[Next]`, `[Replay]`, `[Exit tour]`, «step n/N», підпис кроку з `role="status"`).
5. **`Experiment3D.tsx`:** читає `?tour=<id>` і `sessionStorage`, слухає `agent:tour`. Тур стартує після першого кадру сцени й завантаження кадрів першого кроку. Fallback без WebGL — кроки текстом.
6. **`FramesPanel.tsx`:** виділення кадру на паузі кроку, підпис під ним, попереднє завантаження кадрів моментів туру.
7. **Фіча `agent`:** подія `tour` (тип, `AgentProvider`), навігація чи подія `window`, попереднє завантаження чанка сцени на `tool_start`, згортання панелі на ≤ 600 px. Тести на чисті функції (URL, розбір події).
8. **Документи:** `docs/architecture.md` (потік туру), `docs/agent/README.md` (етап ✅).

**Готово, коли:**
- `npm run build && npm test` зелені;
- у браузері тур #155 іде плавно: переліт без ривків, час без стрибків, ≥ 50 fps на десктопі;
- `[Pause]`, `[Next]`, `[Replay]` працюють, обертання мишею під час туру нічого не ламає;
- на 375 px без горизонтального скролу;
- `prefers-reduced-motion` поважається, консоль чиста.

## Крок 3 — підготовка демо (PR 3, малий)

1. **Перевірити #155 на проді:** числа в підписах = API; кадри D і B на кожному кроці завантажуються; розбіжності `d0` немає.
2. **Підібрати контраст** «без холодного полум'я» за критерієм з `mission.md`, перевірити його так само. Якщо чистого контрасту немає — питання 3 сценарію зробити графіком d² #155 проти #211 (обидва з холодним полум'ям, різний склад атмосфери) і чесно це сказати.
3. **Прогнати 4 питання сценарію на проді** 3 рази поспіль. Записати час до старту туру, ціну й відповіді в `docs/agent/3d-tour/demo.md`, разом зі «шпаргалкою» для доповідача.
4. Якщо агент нестабільно обирає кроки туру, підправити промпт (приклад туру для холодного полум'я) і додати eval-кейс. Не хардкодити тур для #155 у коді.
5. Якщо затримка > 15 с: виміряти, що повільне (rerank, rewrite, сам тур), і запропонувати власнику рішення (див. пам'ять «rerank latency deferred»). Мовчки не вимикати.

**Готово, коли:** 3 прогони поспіль без помилок, числа збігаються, час і ціна в межах цілей з `mission.md`.

## Ризики

| Ризик | Що робити |
|---|---|
| Модель пише цифри в підписах або обирає не ті моменти | валідація в `tour.py` повертає помилку моделі; приклад у промпті; eval-кейс |
| Ривки під час переліту на слабкому ноутбуці | `PerformanceMonitor` → нижчий DPR; на демо — ноутбук із дискретною графікою, перевірити заздалегідь |
| PSI повільно віддає кадри (1–2 с) | попереднє завантаження кадрів моментів туру до старту; тур чекає на кадри першого кроку |
| Автонавігація в момент, коли користувач читає іншу сторінку | тур стартує лише після `done`; `[Exit tour]` повертає звичайний стан; панель чату не закривається |
| Розбіжності табличних і рядових значень (`d0`) | табличні поля — заповнювачі з тегом таблиці, рядові — з тегом ряду, без змішування; на демо — тест без розбіжностей |
| Нечесне «холодне полум'я» | лише підпис із цитатою коментаря NASA, без 3D-об'єкта; слова «likely», «indicative of» зберігати |
